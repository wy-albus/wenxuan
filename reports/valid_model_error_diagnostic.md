# Active-Store Complete Valid 1M 模型误差诊断

## 1. 范围与口径

- 数据：`data/processed/model_dataset_monthly_active_store.parquet` 中 `split=valid` 且 `target_available_1m=1` 的完整样本。
- 样本量：18,563,573，月份为 2025-07 至 2025-12。
- 唯一对齐键：`month + site_no + item_id`；本次在同一数据流中同时生成两个模型预测，不存在跨文件错位。
- LightGBM：`lightgbm_v2_logl2_active_store_wape_1m.txt`，固定使用 850 轮。
- Two-stage：固定使用 classifier 750 轮、regressor 1054 轮，基础预测为 `p_sale * conditional_qty`。
- 本次没有训练、调参、重新选轮、运行 Test、启动 2M 或实现 Hybrid。
- MC 五级沿用 `config/mc_sales_levels.yaml`：0、1、2-4、5-19、20+。

完整推理 5,022.3 秒，汇总 159.1 秒，总计 5,182.3 秒；峰值进程 RSS 约 0.73 GiB。所有预测均通过有限值和非负检查。

## 2. 连续与整数业务评价

整数预测统一定义为：

```text
pred_integer = floor(max(pred_raw, 0) + 0.5)
```

| 范围 | 模型 | Raw WAPE | Integer WAPE | 变化（百分点） | Raw MAE | Integer MAE |
|---|---|---:|---:|---:|---:|---:|
| Overall | LightGBM | 117.1761% | 91.9548% | -25.2213 | 0.1558 | 0.1223 |
| Overall | Two-stage | 134.5989% | 101.9824% | -32.6165 | 0.1790 | 0.1356 |
| Nonzero | LightGBM | 76.8091% | 80.3306% | +3.5215 | 1.6781 | 1.7550 |
| Nonzero | Two-stage | 72.6042% | 75.5189% | +2.9148 | 1.5862 | 1.6499 |

双指标设计是合理的，但用途不同：Raw 指标连续、稳定，继续用于训练选轮和模型内部比较；Integer 指标对应最终交付本数，可作为业务评价。Overall Integer WAPE 的大幅下降主要来自把真实零样本上的小额正预测取整为 0，并不意味着非零需求预测同步改善；事实上两模型的 Nonzero Integer WAPE 都变差。因此不能用 Integer WAPE 替代 Raw WAPE 选 boosting 轮次，也不能只报告取整后的整体指标。

### 关键解释

1. 两模型对所有非零等级都以低估为主，且销量越高，绝对低估越严重。
2. Two-stage 在 1、2-4、5-19、20+ 四组的 WAPE 都更低。它的优势主要来自预测总量更接近真实总量、平均负误差更小、低估比例更低，不是由少数异常值偶然造成。
3. LightGBM 的核心优势在真实零销量：零样本预测总量比 Two-stage 少约 533,891 本，且预测大于 0.5 的比例为 1.38%，低于 Two-stage 的 2.95%。
4. Two-stage 的 Nonzero WAPE 优势为 4.20 个百分点，但多出的零销量误报使 Overall WAPE 反而落后 17.42 个百分点。

## 5. MC 分类诊断

MC 标签均由取整后的销量映射，仅用于评价当前回归结果的等级表达能力。

| 模型 | Accuracy | Macro-F1 | Weighted-F1 | 20+ Recall |
|---|---:|---:|---:|---:|
| LightGBM | 93.4793% | 38.4331% | 92.2807% | 16.1512% |
| Two-stage | 92.4169% | 42.4214% | 92.0676% | 24.5053% |

LightGBM 的总体准确率更高，主要受真实零样本占比支配；Two-stage 的 Macro-F1 和高动销 Recall 更好，更符合其非零及中高销量优势。两者的高动销 Recall 都很低，销量回归误差较小时也不保证 MC 正确，尤其在 1/2、4/5、19/20 边界附近。

## 6. 低成本分层校准可行性

仅使用 2025-07 至 2025-09 学习规律，2025-10 至 2025-12 做时间外验证。校准分组只使用校准前预测等级；为保护零销量，`pred_0` 系数固定为 1。候选系数采用总量比、限制在 `[0.5, 2.0]` 后向 1 做对数半收缩，不进行网格搜索。

- LightGBM 只有 `pred_1-4` 通过初步稳定性检查，收缩后系数为 1.1533；`pred_5+` 因跨月方向和样本稳定性不足不校准。
- Two-stage 各段方向不稳定，所有系数保持 1。

| LightGBM 2025-10~12 | Raw | 校准后 | 变化 |
|---|---:|---:|---:|
| Overall WAPE | 128.2990% | 129.0583% | +0.7593 pp |
| Integer WAPE | 95.9831% | 96.4622% | +0.4792 pp |
| Nonzero WAPE | 79.1432% | 78.4250% | -0.7182 pp |

| 20+ WAPE | 91.8595% | 91.6625% | -0.1970 pp |

校准确实略微改善非零、中等销量和总量偏差，但整体 Raw/Integer WAPE 变差，零销量预测总量增加约 14,545 本，零样本预测大于 1 的比例由 0.288% 升至 0.395%。收益小且月份规律不稳定，当前不值得正式部署 MC 分层乘法校准。若以后重试，应先解决季节异质性，并继续使用时间外验证，而不是扩大系数搜索。

## 7. 两模型逐样本互补性与 Oracle 上限

| 指标 | 结果 |
|---|---:|
| LightGBM 逐行胜率 | 79.4576% |
| Two-stage 逐行胜率 | 20.5417% |
| 绝对误差差不超过 0.05 的比例 | 83.1456% |
| 残差相关性 | 0.9730 |
| 绝对误差相关性 | 0.9793 |
| 最好单模型 Raw WAPE | 117.1761%（LightGBM） |
| Oracle Raw WAPE | 106.9845% |
| Oracle 相对最好单模型上限 | 8.70% |
| 最好单模型 Integer WAPE | 91.9548%（LightGBM） |
| Oracle Integer WAPE | 81.7919% |
| Oracle 相对最好单模型上限 | 11.05% |

总体胜率被 1,743 万个零样本主导。只看非零样本，Two-stage 约有 85.2% 的逐行胜率；在 1、2-4、5-19、20+ 四组的胜率分别为 85.04%、86.10%、82.55%、87.23%。这说明两个模型的业务分工真实存在，但可部署路由条件仍未找到。

按 `p_sale` 分段后，LightGBM 在每个区间的聚合 WAPE 都更低；Two-stage 胜率虽从低概率区约 15%-23% 上升到高概率区约 41%，但从未超过 LightGBM。六个月中 LightGBM 的 Overall WAPE 也均更低。由于真实销量等级不能用于线上路由，仅靠 `p_sale < tau` 的简单 Hybrid 目前没有充分依据。

Oracle 比最好单模型低约 10.19 个 Raw WAPE 百分点，说明如果能可靠识别真实动销样本，理论上仍有空间；但 83.1% 样本近似打平、残差高度相关，Oracle 又直接使用了真实标签，所以该上限不能视为可实现收益。下一轮若研究 Hybrid，应先在 Valid 内构造一个非常小、可解释、仅使用当时可得信息的路由诊断，并做月份时间外验证，不应直接上线融合或训练复杂门控器。

## 9. 明确结论与优先级

### 核心问题回答

1. **取整是否明显改变业务 WAPE？** 是。Overall WAPE 分别下降 25.22 和 32.62 个百分点，但 Nonzero WAPE 反而上升；下降主要来自零样本小额预测被取整为 0。Raw 与 Integer 两套指标都应保留。
2. **各销量区间主要高估还是低估？** 两模型对真实 0 高估，对 1、2-4、5-19、20+ 均系统性低估。Two-stage 在所有非零组低估程度更小，LightGBM 对零销量控制明显更好。
3. **Two-stage 中高销量优势来自什么？** 来自更高且更接近真实值的预测总量、更低的低估比例和更小的负误差；不是仅靠少数样本，也不是整体高估带来的表面改善。
4. **预测 MC 是否存在跨月稳定校准规律？** 不足。真实等级下的低估很稳定，但真实等级不可部署；预测等级下偏差会随月份翻转，静态分段系数不稳定。
5. **简单 MC 分层校准是否值得做？** 当前不建议。唯一通过初筛的 LightGBM pred_1-4 校准在后半 Valid 改善 Nonzero WAPE，却恶化 Overall/Integer WAPE并增加零销量误报。
6. **两模型是否有逐样本互补性？** 有结构性互补：LightGBM 擅长零销量，Two-stage 擅长非零和中高销量。Oracle Raw WAPE 上限约比最好单模型相对改善 8.70%。但可部署的简单 `p_sale` 路由证据不足，残差也高度相关。
7. **是否值得下一轮直接做 Hybrid？** 不建议直接实现正式 Hybrid。可以先做受限的、仅 Valid、按月份时间外验证的小型路由可行性实验；若路由规则不能稳定识别非零优势区，应停止。
8. **整数趋势是否更合理？** 是，业务语义显著更合理；但上涨 Recall 很低，必须与高 Accuracy 一并披露。

### 建议优先做

**优先修改 Two-stage 的“零销量控制 / 分类概率质量”，而不是先改正销量 regressor。** 当前 regressor 组合在真实非零和中高销量上已经优于 LightGBM，主要矛盾是零样本累计出大量小额正预测。下一步最小成本实验应只在 Valid 上检验可部署的分类概率校准或受约束软门控，并以零误报、Nonzero WAPE、5-19/20+ 保护同时作为约束。

### 可以后做

**小型 Hybrid 路由可行性实验。** Oracle 显示存在理论空间，但应限制为少量可解释候选，采用 2025-07~09 选择、2025-10~12 验证；不能按真实 MC 路由，也不能使用 Test。只有时间外收益稳定才值得进入正式实现。

### 不建议做

- 当前不建议正式部署静态 MC 分层乘法校准。
- 不建议把 Integer WAPE 用作 boosting 选轮标准。
- 不建议基于真实未来 MC 做校准或融合路由，这会造成目标泄露。
- 不建议立即重训正销量 Tweedie regressor；现有证据显示主要瓶颈在 classifier / 组合对零销量的处理。
- 不建议为了追求 Oracle 上限直接训练复杂门控模型；现阶段容易把 Valid 偶然规律当作可泛化规律。
